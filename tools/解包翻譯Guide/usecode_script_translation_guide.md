# U7 Usecode 腳本 (`.uc`) 翻譯與修改指南

這份文件專為參與 Ultima 7 (創世紀 7) 漢化與改版的翻譯人員所撰寫。當程式人員使用 `ucxt -fa` 提取出遊戲的腳本檔案 (`.uc` 檔) 後，翻譯人員請遵循以下規範進行文字的漢化作業。

---

## 1. 什麼是 `.uc` 腳本檔案？
`.uc` 檔是遊戲核心邏輯的「組合語言 (Assembly)」腳本。它包含了遊戲中所有的對話、系統提示，以及底層的邏輯判斷。身為翻譯人員，我們**只需要看懂並修改特定的區域**即可，完全不需要具備寫程式的能力！

---

## 2. 檔案結構解讀：我該看哪裡？

當你打開 `.uc` 檔案時，你會看到每個事件 (Function) 都被分為三個區塊，請認明 **`.data`** 區塊：

```uc
	; Function at file offset 00000000H
	.funcnumber  0096H          <-- 【函數宣告區】不要動它

	.data                       <-- 【資料區】🎯 你的主要戰場
	.msize       00A2H
	.dsize       005DH
L0000:	db	'@The sails must be furled before the planks are raised.@'
	db	00
L0039:	db	'@I think the gangplank is blocked.@'
	db	00

	.code                       <-- 【程式碼區】🚫 絕對不要動它
	.argc        0001H
0000:	push	eventid
0001:	pushi	0001H
```

*   **你的任務**：在整個檔案中尋找 `.data` 下面的 `db '...'` 字串，並將單引號內的英文翻譯成中文。

---

## 3. 翻譯實戰與排版自由

編譯器 (`wuc`) 非常聰明，它不會管你寫了幾行、字數多長，它只認得規定的語法。因此在翻譯長篇大論時，你可以自由決定要怎麼排版。

### 情境：遇到超長對話
原本的英文可能會因為太長，被切成很多個 `db`：
```uc
L07F3:	db	'"Here we are. Now then, it appears to be written in a strang'
	db	'e format. One might even say a code of sorts... I have it! A'
	db	'pparently, the Talisman currently resides in the Great Void.'
    ...
	db	00
```

### 👉 翻譯法 A：縮成一行 (最省事)
你可以把所有的 `db` 刪掉，只保留第一行的標籤，把中文全部塞進去：
```uc
L07F3:	db	'"我們到了。看起來這是一份奇怪格式的文件。有人可能會說這是一種密碼... 我懂了！看來護身符目前存在於大虛空之中。(後面省略)"'
	db	00
```

### 👉 翻譯法 B：按句號換行 (適合閱讀)
如果你覺得一行太長不好對照，你可以自己切行，只要確保每行開頭都有 `db` 即可：
```uc
L07F3:	db	'"我們到了。'
	db	'看起來這是一份奇怪格式的文件。'
	db	'有人可能會說這是一種密碼... 我懂了！'
	db	'看來護身符目前存在於大虛空之中。"'
	db	00
```

> [!TIP]
> **翻譯後的字數不一樣怎麼辦？**
> 完全不用擔心！官方打包工具在編譯時，會自動重新計算所有中文字串的新長度與位置（偏移量），絕不會因為字數改變而導致遊戲當機。

## 4. 💡 特殊符號的處理：`@` 與 `~`

在原本的英文腳本中，你可能會看到一些特殊的符號，它們是當年遊戲引擎為了排版方便而設計的，在翻譯時可以依據情況替換或保留：

### `@` 符號 (對話雙引號)
在原版 U7 字庫中，`@` 的圖案其實被畫成了**雙引號 (`"`)**，用來標示人物說話。
*   **如何翻譯**：強烈建議直接替換成中文的全形引號（如 `「` 和 `」`，或是 `“` 和 `”`），或是依照你們漢化團隊的字庫設定來決定是否保留 `@`。
*   **改法範例**：`db '@你好@'` 翻譯時請直接寫成 `db '「你好」'`。

### `~` 符號 (等待玩家點擊)
在對話中看到 `~`，代表遊戲文字跑到這裡會**暫停，並等待玩家點擊滑鼠**才會繼續顯示下一句。
*   **如何翻譯**：請依照中文語氣的停頓點，保留這個符號在句子中間或結尾。
*   **改法範例**：`db '你好，~很高興見到你。'`

### `*` 符號 (段落結束)
對話中的 `*` 通常代表一個段落的結束（或是對話框強制換行）。翻譯時請記得將它保留在相對應的句尾。

## 5. ⚠️ 翻譯者的絕對禁忌 (避免編譯失敗)

在修改文字時，請務必遵守以下三大鐵則，否則會導致檔案毀損或無法打包：

### 🚫 禁忌一：絕不能刪掉頭尾的「單引號」與「標籤」
正確：`L0000:  db  '這是中文'`
錯誤：`L0000:  db  這是中文` (少了單引號)
錯誤：`db '這是中文'` (不小心把最前面的 `L0000:` 標籤刪掉了)

### 🚫 禁忌二：絕不能刪掉結尾的 `db 00`
`db 00` 對電腦來說代表「這句話說完了」。每個字串區塊的最後一行一定要保留它。
正確：
```uc
L0000:	db	'這是中文翻譯'
	db	00    <-- 必須保留
```

### 🚫 禁忌三：原文裡的單引號要加上反斜線 `\`
如果你的翻譯中需要用到半形的單引號 `'`，請務必在前面加上反斜線 `\`，否則電腦會以為字串提早結束了。
*   原文範例：`I\'m famished!`
*   錯誤寫法：`db  '這是'蘋果''` (中間的單引號會讓程式搞混)
*   正確寫法：`db  '這是\'蘋果\''`

### 🚫 禁忌四：絕不能合併「不同標籤」的字串
如果兩段話都有自己的標籤（例如 `L06E1:` 和 `L070E:`），**絕對不可以把它們合併成一句！**
這種情況通常是因為遊戲會在兩句話「中間」插入玩家的名字或其他變數。
*   **錯誤範例（會導致遊戲崩潰或顯示錯誤）**：
    把 `L06E1` 和 `L070E` 的內容全部寫在 `L06E1` 裡，然後刪除 `L070E`。

### 💡 進階技巧：遇到中英文法不同時，如何翻譯被切斷的句子？
因為遊戲引擎輸出的順序是寫死在程式裡的（`標籤 A` + `變數` + `標籤 B`），遇到中英文文法結構不同時，**千萬不能直譯，必須前後對照來「意譯」**，讓中文拼起來順暢。

**❓ 我要怎麼看出哪些句子是被切斷、需要拼接的？**
對於不懂程式碼的翻譯人員，你可以透過以下三個「肉眼觀察法」來精準判斷：
1. **看標點符號與語氣**：這是最明顯的特徵。如果一句話結尾沒有句號，甚至停在逗號、空格，而下一句開頭也是逗號或小寫字母，那這兩句絕對是一體的。
   *範例：`db '"My name, '` 與 `db ', is Robin."'`*
2. **看對話引號 (`"` 或 `@`) 是否成對**：對話通常會有開頭與結尾的引號。如果某個標籤只有開頭引號 `"`，而另一個標籤只有結尾引號 `"`，那它們就是同一句話被切開了。
3. **看它們在檔案裡的位置**：需要拼接的句子，在 `.data` 區塊中通常**會緊挨在一起**（或是中間只夾著幾個單字標籤如 `name`、`job`）。

> [!TIP]
> **翻譯人員的定心丸：需要跨區找下半句話嗎？**
> **絕對不需要！** 由於遊戲底層運作邏輯的關係，一段對話的「前半句」與「後半句」**絕對「一定」會存在於同一個 function 的 `.data` 區塊內**。你完全不用擔心要跨 function 或跨檔案去海底撈針，只要在附近上下幾行找，一定能找到它的另一半！

**實戰範例（改變句型）**：
*   **英文原文**：
    `L1: db 'I need to give this '`
    `（插入變數：Apple）`
    `L2: db ' to the king!'`
*   **如果硬是直譯（會很怪）**：
    `L1: db '我需要給這個 '`
    `L2: db ' 給國王！'`  -> 變成：「我需要給這個蘋果給國王！」
*   **正確的語意潤飾寫法**：
    `L1: db '我必須將這顆 '`
    `L2: db ' 獻給國王！'` -> 變成：「我必須將這顆蘋果獻給國王！」

即使英文文法順序在中文裡很難對應，翻譯人員也要發揮創意，用不同的句型把這兩個洞補起來，**絕對不能去修改底下的 `.code` 程式碼來改變輸出順序**。

## 6. 💡 實用技巧與突發狀況處理

### 遇到奇形怪狀的亂碼 (如 ``) 怎麼辦？
在這種 1990 年代的老遊戲腳本裡，偶爾會看到這類「歷史痕跡」（開發者當年不小心按到控制鍵、或是輸入法當掉產生的無效字元）。
*   **處理方式**：請直接**無視並刪除它**！只要依靠前後文（例如 `"Yes,  friend?"` 明顯是 `"Yes, my friend?"`）來判斷原意，當作正常的句子翻譯成中文即可，千萬不要把亂碼保留下來。

### 善用分號 `;` 來寫團隊翻譯筆記
在組合語言中，分號 `;` 開頭的整行就是**註解 (Comment)**。編譯器在打包時會完全忽略它。
如果你在翻譯時想留一些備註給校對人員，或是想標記「這句我還不確定」，可以直接在程式碼裡面用 `;` 來寫註解！
*   **範例寫法**：
```uc
L18D7:	db	'"\'Tis always a pleasure to speak with thee, my friend."*'
	; 這句的 my friend 應該是指 Iolo，我先翻成「老友」，需要校對確認。
	db	00
```
這樣寫是完全安全的，不但可以當作團隊協作的筆記本，也不會造成打包出錯！

## 7. 翻譯完成後如何打包？

當翻譯人員修改完 `.uc` 檔案後，程式人員只需使用 Exult 內建的 `wuc` 工具進行重新編譯：

```bash
# 指令範例 (將 blackgate_script.uc 編譯成新的 USECODE 檔)
wuc -bg blackgate_script.uc USECODE.new
```

編譯完成的 `USECODE.new` 只要改名為 `USECODE` 並放入遊戲的 `STATIC` 資料夾，就可以進遊戲測試你們的翻譯成果了！
