# U7 Usecode 腳本進階解析：看懂 `.code` 邏輯區塊

這份文件專為對 Usecode 底層運作邏輯感興趣、或是需要深入除錯的團隊成員所撰寫。
在一般的翻譯工作中，我們只需要專注於修改 `.data` 區塊的文字即可。但如果想要了解遊戲是如何決定「何時說出哪句話」，或是想確認為什麼某個句子會被切斷，看懂底下的 `.code` 區塊將會非常有幫助。

---

## 1. 說話的核心秘密：`addsi` 與 `say`

在 Usecode 中，所有的對話顯示都是由兩個步驟組合而成的：「把字串抓在手上」以及「把它說出來」。

*   **`addsi` (Add String Immediate)**：準備好指定的文字標籤。
*   **`say`**：將剛剛準備好的內容顯示在畫面上。

**範例：**
```uc
005E:	addsi	L0000    ; 電腦去 .data 區塊把 L0000 的句子抓過來
0061:	say              ; 在畫面上彈出這句話！
```

---

## 2. 插入變數與名字：`addsv` 

有時候遊戲會在對話中插入玩家的名字或特定的地名，這時候就會用到「字串變數」。

*   **`addsv` (Add String Variable)**：抓取一個會變動的內容（例如變數盒子 `[0003]` 裡面的字）。
*   **`[0003]` (Local Variable)**：區域變數。你可以把它想像成一個暫時用來裝資料的小盒子。

**範例（三段式拼圖）：**
```uc
0370:	addsi	L06E1    ; 抓出前半句 (例如："你好啊，")
0373:	addsv	[0003]   ; 打開 [0003] 盒子，抓出裡面的名字 (例如："Avatar")
0376:	addsi	L070E    ; 抓出後半句 (例如："，今天過得好嗎？")
0379:	say              ; 把手上的東西一口氣拼起來說出："你好啊，Avatar，今天過得好嗎？"
```

> [!WARNING]
> **翻譯警告**
> 當你看到這種結構時，**絕對不可以**把 `L06E1` 和 `L070E` 的文字合併。因為這會導致 `[0003]` 變數無處安放，造成遊戲崩潰。你必須用「意譯」的方式，讓中文圍繞著這個變數拼湊通順。

## 3. 條件判斷與跳躍：`jne` 與 `jmp`

遊戲怎麼知道玩家有沒有解過任務？這就要靠檢查旗標 (Flag) 和跳躍指令來完成。這就等於是程式語言裡面的 `If / Else`。

*   **`jne` (Jump if Not Equal)**：如果不符合條件，就**跳躍**到指定的行數。
*   **`jmp` (Jump)**：無條件直接**跳躍**到指定的行數。

**範例（對話分歧）：**
```uc
0062:	call	extern:[0003]  ; 檢查某個條件 (例如：玩家回答 YES 嗎？)
0065:	jne	0072           ; 【如果不是 YES】，跳到 0072 行！
0068:	addsi	L0041          ; (如果是 YES，沒被跳過) 準備第一種回答
006B:	say                ; 說出第一種回答
006C:	jmp	0076           ; 說完後，直接跳到 0076 行離開 (避開下面的對話)
0072:	addsi	L00A2          ; (剛才 0065 行跳過來的地方) 準備第二種回答
0075:	say                ; 說出第二種回答
0076:   ...                ; 繼續後續的邏輯
```

## 4. 呼叫函數：`call` 與 `callis`

你可能會在腳本中看到兩種不同的呼叫指令：

### `call` / `calle` (呼叫腳本函數)
*   **用途**：呼叫寫在 `.uc` 腳本檔案裡面的其他 Function。
*   **範例**：`calle 0269H` 代表去尋找這份腳本（或其他腳本）裡面的 `.funcnumber 0269H` 並執行它。

### `callis` (Call Intrinsic System - 呼叫系統函數)
*   **用途**：呼叫 **Exult 遊戲引擎底層 (C++ 原始碼)** 內建的功能。
*   **特徵**：在腳本裡面絕對找不到它的定義。
*   **範例**：`callis get_npc_object@01` 這是請遊戲引擎直接回傳某個 NPC 的物件資料。

> [!TIP]
> **小知識：編譯時的大小重算**
> 在 `.data` 區塊上方的 `.msize` 和 `.dsize` 是用來記錄記憶體大小的。但當我們用 `wuc` 重新打包時，編譯器會**完全忽略**舊的數值，並根據你翻譯後的新字串長度，自動且精準地重新計算這些大小與偏移量，所以翻譯人員完全不用擔心字數增減的問題！
